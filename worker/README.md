# Waypoint sync worker

The entire server. It holds one JSON blob per sync code and hands it back —
everything that makes sync hard happens on the phone, in `src/sync/`.

## What it costs

Nothing, on Cloudflare's free plan, and not in a way that expires:

- Workers free tier: 100,000 requests/day. A sync is one GET and one PUT.
- R2 free tier: 10 GB stored, 1M writes and 10M reads a month.
- Nothing pauses for inactivity, which matters for an app you might not open
  for three weeks between trips.

## Deploying it

You need a Cloudflare account. There is no card required for this.

```bash
npm install -g wrangler        # or npx wrangler
cd worker
wrangler login
wrangler r2 bucket create waypoint-snapshots
wrangler deploy
```

`wrangler deploy` prints a URL like `https://waypoint-sync.<you>.workers.dev`.
Put that into the app under **Settings → Sync with another device**.

## The security model, stated plainly

The sync code is the only credential. Anyone who has it can read and write that
trip's data; anyone who does not cannot guess it — the codes are 26 characters
from a 32-symbol alphabet, which is about 130 bits.

That is the trade for having no accounts. It is a deliberate one: an account
system would mean passwords, resets, email, and a database of people, all so
that a trip planner can hold your restaurant bookings. If you would rather not
make that trade, do not use this — the app syncs by passing a backup file
between devices with no server at all, and that path is not going away.

Codes are generated by the app, never typed by a person. The Worker refuses
anything that does not match the expected shape rather than accepting a short
code somebody chose themselves.

## What it does not do

No accounts, no authentication beyond the code, no per-device history, no
conflict resolution. The last one is the point: the device merges before it
writes, so the server never has to decide anything.
